# 🛠️ תיקונים לאתר cyberguard.co.il

נבדק ב‑6.11.2026 בדפדפן אמיתי, בנייד (390px) ובמחשב (1366px). הבדיקה רק קראה את האתר, ושום דבר בו לא השתנה.
המדריך מסודר לפי סדר ההשפעה. כל שלב כתוב כך שאפשר לבצע אותו לבד בממשק הניהול של וורדפרס.

**המצב לפני התיקונים (נייד):** 89–93 בקשות, כ‑1.1MB, וכ‑5 שניות עד שהעמוד נטען. הגובה הוא כ‑13,000px, כלומר כ‑15 מסכים.
**למה זה חשוב לפרסום:** בקמפיינים של מטא, רק 47%–65% ממי שלחץ על המודעה הגיע בפועל לעמוד. השאר יצאו לפני שהעמוד נטען.

> לפני שמתחילים: כדאי לגבות את האתר (ב‑WP Rocket או אצל חברת האחסון), ולבצע את השלבים אחד אחד, עם בדיקה בטלפון אחרי כל שלב.

## שלב 1 — להוריד את החלון הקופץ בנייד (5 דקות) 🔴

בנייד נפתח החלון "רגע לפני שאתם יוצאים…" (Popup מספר **5777** של Elementor Pro) כבר בזמן גלילה, ומעל באנר העוגיות.

1. **תבניות ← Popups** ← לפתוח את ה‑Popup "רגע לפני שאתם יוצאים" (מספר 5777).
2. **Publish ← Advanced Rules** ← להפעיל את **Show on devices** ולסמן **Desktop בלבד**.
3. ב‑**Triggers**, להשאיר רק **On Page Exit Intent**, שעובד רק במחשב, ולבטל טריגרים של גלילה.
4. לשמור, לנקות מטמון ב‑WP Rocket, ולבדוק בטלפון.

> גוגל מורידה בדירוג עמודים שחלון קופץ מכסה בהם את התוכן בנייד.

## שלב 2 — באנר עוגיות קטן בנייד (10 דקות) 🔴

באנר התוסף **Cookie Consent by Elementor** (‏Cookiez) מכסה **46% מהמסך הראשון בנייד**, כולל הכפתור "שחזרו את החשבון עכשיו". הבאנר בנוי בתוך רכיב סגור (Shadow DOM), כך ש‑CSS רגיל של האתר לא משפיע עליו.

**מה בדקתי (6.11.2026):** האתר טוען היום `"bannerType":"box"`, גם כשעוקפים את המטמון, כלומר ההגדרה עוד לא שונתה. בדפדפן שלי, בלי לגעת באתר, הדמיתי שינויים בהגדרות:

| שינוי (הדמיה מקומית) | גובה הבאנר בנייד |
|---|---|
| היום (Box, כותרת 20, טקסט 14) | **46%** מהמסך |
| מעבר ל‑Banner (פס) | 44% |
| Banner + כותרת 15 + טקסט 13 | 42% |

**המסקנה:** עצם המעבר לפס כמעט לא עוזר. הגובה מגיע מ**הטקסט הארוך** (6 שורות), מ**שלושה כפתורים שנערמים אחד מתחת לשני** ומ**השורה "by Cookie Consent"**.

מה עושים, לפי הסדר:
1. בהגדרות התוסף, בחלק של **התוכן (Content)**: לקצר את הטקסט למשפט אחד, למשל: "אנחנו משתמשים בעוגיות לשיפור האתר ולמדידה. [מדיניות פרטיות]".
2. בחלק של **העיצוב (Design)**: להקטין את גודל הכותרת ל‑15 ואת הטקסט ל‑13.
3. להסתיר את השורה **Powered by** אם התוכנית מאפשרת זאת. בהדמיה שלי ההגדרה הזו העלימה את הבאנר כולו, ולכן חובה לבדוק בטלפון שהבאנר עדיין מופיע ושההסכמה נשמרת.
4. לשמור, **לנקות מטמון ב‑WP Rocket**, ולבדוק בטלפון בחלון גלישה פרטית.
5. אם הבאנר עדיין תופס יותר מכשליש מהמסך: לשקול קוד קטן שמזריק עיצוב לתוך הרכיב (`#cookiez-banner`, ה‑Shadow DOM פתוח) ומסדר את הכפתורים בשורה אחת. אחרי זה צריך לבדוק היטב ש"קבל הכל", "דחה" ו"התאמה" עובדים.

> ההחלטה אם לתת ל"דחה" אותו משקל כמו ל"קבל הכל" היא ענין משפטי, וכדאי להתייעץ עליה. **היעד:** באנר בתחתית שתופס לכל היותר כרבע עד שליש מהמסך.

## שלב 3 — אייקונים: לחסוך כ‑270–370KB (10 דקות) 🔴

Font Awesome נטען **פעמיים**: פעם מתוך Elementor, ופעם גרסה 6.5.2 מ‑cdnjs.cloudflare.com, דרך CSS שנוסף ידנית. הקבצים מ‑cdnjs לבדם שוקלים 268KB, יותר מכל התמונות בעמוד ביחד.

1. **Elementor ← הגדרות ← Features ← Inline Font Icons ← Active.** עם ההגדרה הזו האייקונים מוטמעים כ‑SVG, ולא נטענים כגופנים.
2. **Elementor ← הגדרות ← Advanced ← Load Font Awesome 4 Support ← No.**
3. למצוא ולמחוק את ה‑CSS שטוען את `cdnjs.cloudflare.com/ajax/libs/font-awesome/6.5.2`. בדרך כלל הוא נמצא באחד מהמקומות האלה:
   - **Elementor ← Custom Code**
   - **Elementor ← Site Settings ← Custom CSS**
   - **עיצוב ← התאמה אישית ← CSS נוסף**
4. לבדוק שכל האייקונים באתר עדיין מוצגים, למשל וואטסאפ, טלפון והסימנים ✓.

## שלב 4 — לדחות סקריפטים חיצוניים עם WP Rocket (15 דקות) 🔴

בכל טעינת עמוד רצים 8 שירותים חיצוניים: GTM, ‏Google Ads, ‏Site Kit, ‏Clarity, ‏Outbrain (שני קבצים), Google Call Tracking, ‏Clixtell ופיקסל פייסבוק.

1. **WP Rocket ← File Optimization:**
   - **Load JavaScript deferred** ← מופעל
   - **Delay JavaScript execution** ← מופעל. הסקריפטים ירוצו רק אחרי הנגיעה או הגלילה הראשונה
2. **לא** לדחות את הסקריפט של באנר העוגיות (`cookiez/…/banner.js`), אחרת ההסכמה לא תעבוד. אם משהו נשבר, להוסיף אותו לרשימת **Excluded JavaScript Files**.
3. **WP Rocket ← Media ← LazyLoad** לתמונות, ל‑iframes ולסרטונים ← מופעל.
4. לבדוק אחרי השינוי:
   - שליחת טופס, ושהליד מגיע
   - לחיצה על וואטסאפ
   - שאירועי Lead ו‑PageView ממשיכים להגיע ב‑Events Manager של מטא (פיקסל "סייבר גארד")

## שלב 6 — מבנה הכותרות (20 דקות) 🟡

| הטקסט היום | התג היום | צריך להיות |

## שלב 7 — מספרים שסותרים זה את זה (15 דקות) 🟠

בתחום שהתקשורת מזהירה בו מהונאות, כל מספר שלא מסתדר פוגע באמון. מה שמופיע היום:

- "מעל 2,000 מקרים שטופלו **בשנה האחרונה**" (באזור הראשון של העמוד)
- "מעל 2,000 חשבונות שטופלו" (בלי ציון תקופה)
- "עם ניסיון בטיפול ב**מאות** מקרים מורכבים" (באודות)
- "**98%** הצלחה בשחזור חשבונות" (בטופס התחתון)
- "**100%** תמחור ברור מראש"
- "CyberGuard: **המגן המוביל** שלך בעולם הסייבר"

**ההמלצה:**
- לבחור מספר אחד ואמיתי, מתוך אפליקציית הניהול, ולהציג אותו בכל מקום באותו נוסח.
- להוריד את "98%" ואת "המוביל", אלא אם אפשר להוכיח אותם. זה גם ענין של הגנת הצרכן.
- "100% תמחור ברור מראש" ← "תמחור ברור מראש".

- בהגדרות התוסף, להעביר את הכפתור לפינה **התחתונה** (שמאל או ימין, בצד שבו אין את כפתור הוואטסאפ).
- חשוב לדעת: סרגל נגישות לבדו לא מספיק כדי לעמוד בתקנות. צריך גם את התיקונים בתוך האתר (כמו שלב 6) והצהרת נגישות מעודכנת.
